# Qwen 插件包优化版 1.3.1-qwen.2

这是基于 Alibaba 插件的私有扩展，不是 QuantumNous 官方发布。保留 `alibaba` 插件键，支持原有 Wan 分支及两款 Qwen Image 3.0 模型。

## 本版做了什么

1. **输入保护**：提前拒绝格式损坏/空内容的 Base64 图片数据、缺失主机的 URL、错误端口、空白/控制字符、内嵌账号密码的 URL。支持合法 HTTP(S) 地址、签名查询参数和 Base64 data URL；不联网校验图片，也不解码验证图片内容。
2. **原厂错误提示**：插件能够收到的原厂错误，按参数、限流、鉴权、额度、内容安全分类提示；保留合法 UUID 请求 ID，不直接回显可能含密钥或签名链接的原厂自由文本。HTTP 非 2xx 若由宿主先行处理，不在本插件控制范围内。
3. **结算校验**：继续检查输入/输出张数、计费档位、实际图片数量；补充返回状态矛盾、可选尺寸字段错误、输出图片 URL 格式异常校验。异常产生 `QWEN_USAGE_RECONCILIATION` 诊断，不凭空生成零费用或推测用量。
4. **异步不确定状态**：`UNKNOWN`、查询报错、原厂声称成功但无图片，不再被插件直接认定为确定失败。明确 `FAILED` / `CANCELED` 仍走失败状态。本插件不会自动重新提交生成请求。

## 保持不变

- 模型名、接口路径、默认参数、原有同步/异步调用方式。
- 四项用量字段：`qima_input_1k`、`qima_input_2k`、`qima_output_1k`、`qima_output_2k`。
- 计价公式及自动尺寸预扣方式。由 `1.3.1-qwen.1` 升级无需改价格；仍要求配置任务用量表达式。
- 使用原厂返回档位，不将 `2K` 强制视为 `2048×2048`。`2528×1696` 自动尺寸有回归覆盖。
- Wan 原有分支的行为。

## 明确没有做

- 没改 NewAPI 主程序、前端、数据库结构、鉴权和价格配置。
- 不修复界面“耗时 0.0s”“计费无匹配结果”和零余额 `Invalid token`。
- 没实现全局幂等、跨重启恢复、持久化待对账队列或无限期冻结余额。
- `UNKNOWN` 的后续重查、超时、最终结算仍由宿主策略决定；本插件不能保证未知任务永远不被宿主判失败或退款。
- 抛出用量校验错误不等于创建了宿主的“待对账状态”；必须根据日志与原厂账单人工核查。
- 没有新的原厂付费测试，不把模拟测试算作真实供应商账单验收。

## 验证结果（2026-09-17）

- Node 插件回归：149/149 通过。
- 与测试实例相同的 NewAPI `v1.0.0-rc.37` 镜像，Sobek 插件运行时回放：同一组 149/149 通过。不是 298 个不同用例。
- `pluginindex generate` / `check` 通过。
- 包含原有有效请求与计费场景、两款 Qwen 新增异常输入/状态/结算校验，以及 Wan 请求、用量和状态回归。
- 运行时测试使用禁网、只读、限资源的一次性容器，不访问运行实例数据库，未替换在线插件。

## 安装与回滚

1. 先导出当前 `alibaba` 插件源码与配置，确认已有 Qwen 任务完成或已记录需对账任务。
2. 在 NewAPI 的任务插件管理中导入本包 `plugin.js`。同一 `alibaba` 键会替换该插件活动版本，不是额外并行渠道。
3. 检查注册状态及版本 `1.3.1-qwen.2`，保留已有渠道绑定和定价；不要直接导入整个开发仓库的市场索引。
4. 在你的环境先验证合法请求、非法图片拦截、异步查询及用量结算，再放量。尚未有本版在活动实例上的端到端调用验收。
5. 如出现兼容问题，重新导入备份的旧插件；不要删除任务数据，不要因未知状态直接再次生成。

运行时回归命令：

```sh
new-api plugin test plugin.js --fixture runtime.fixture.json
```
